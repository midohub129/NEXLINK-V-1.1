5.1 إلزامية الحاجز (Mandatory Barrier):
- **في الشيفرة الحالية [CRITICAL]:**
  * لا يوجد `IDatabaseWriteBarrier` ولا `RestoreCoordinator` في `src/`.
  * `IndexedDbDatabase` (`src/infrastructure/storage/indexedDbDatabase.ts:137`) يقبل `dbName` فقط بلا حاجز.
  * `enqueueWrite` (`indexedDbDatabase.ts:249`) ما زالت `public` ويمكن استدعاؤها مباشرة لتجاوز الدوال العليا.
  * لم يُطبَّق أي فحص في `put` (258)، `add` (267)، `deleteKey` (276)، `clearStore` (284)، أو `runTransaction` (292).
- **في التصميم المقترح [CRITICAL — خلل في التصميم نفسه]:**
  * في `HYDROGEN_PHASE2_DESIGN.txt:388-414`، يتحقق المُنشئ عبر الدالة:
    ```ts
    function isValidWriteBarrier(candidate: unknown): candidate is IDatabaseWriteBarrier {
      if (!candidate || typeof candidate !== 'object') return false;
      const barrier = candidate as Partial<IDatabaseWriteBarrier>;
      return (
        typeof barrier.isWriteBlocked === 'function' &&
        typeof barrier.assertWriteAllowed === 'function'
      );
    }
    ```
  * هذا الفحص **فحص شكلي بحت (Structural Duck-Typing)**! أي وحدة برمجية داخل `src/` تستطيع تمرير كائن وهمي مثل `{ isWriteBlocked: () => false, assertWriteAllowed: () => {} }` مباشرة إلى `new IndexedDbDatabase({ writeBarrier: fake })` فينجح المُنشئ بلا خطأ ويُعطل الحاجز تماماً دون استدعاء `createUnprotectedIndexedDbForTestsOnly` ودون مخالفة قاعدة `no-restricted-imports` في ESLint!
  * لكي يكون الإلزام حقيقياً غير قابل للتجاوز، يجب إما اشتراط علامة سرية غير مصدرة (module-private Symbol/WeakSet أو `instanceof RestoreCoordinator` / `AuthorizedWriteBarrier` مع إنشاء الحاجز الاختباري حصراً عبر مصنع خارج `src/` أو بمصادقة داخلية محظورة بـ ESLint في `src/`).

- **في التصميم المقترح [HIGH — ثغرة تجاوز عبر `AppContainer.backupProvider`]:**
